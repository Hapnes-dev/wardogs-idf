# Google Play submission pack

Everything needed to create the listing, with the text ready to paste and the
assets already at Play's required sizes. The steps only you can do are marked
**you**: account creation, payment, accepting agreements, entering passwords,
and pressing Publish.

---

## 1. Before anything else

| Item | Status |
|---|---|
| Play Console developer account, one-time 25 USD | **you** |
| Accept the Developer Distribution Agreement | **you** |
| 12 testers running a closed test for 14 consecutive days | **you** — required for new personal accounts before production access opens. The clock does not start until the twelfth tester has opted in. |
| Upload keystore | **you** — see section 6 |

A developer account registered as an organisation skips the 12-tester rule but
needs a D-U-N-S number.

## 2. Store listing text

**App name** (30 char limit, currently 11)

```
WARDOGS IDF
```

**Short description** (80 char limit, currently 76)

```
Offline mortar and artillery firing solutions from two map grid coordinates.
```

**Full description** (4000 char limit)

```
Enter your gun position and the target position as map grid coordinates. WARDOGS IDF reports the range, the bearing, the compass direction and, for the L81 mortar, the estimated sight elevation in mils. The solution updates as you type.

One full grid square counts as 100 meters.

WHAT IT DOES
• Range in meters and bearing in degrees from two grid references
• Eight-point compass direction
• Estimated L81 elevation in mils, interpolated from the in-game sight markings
• Easting and northing offsets, so the plot can be sanity-checked
• Range checking against each weapon's effective envelope, with an explicit error instead of a bogus solution

WEAPONS
• L81 Mortar — 120 to 700 m
• SPH-2 Artillery — 735 to 2,630 m

BUILT FOR A SECOND SCREEN
No network permission, so the app cannot open a connection at all. No accounts, no ads, no analytics, no tracking. It works in flight mode and stores nothing between launches.

NOTE
Elevation is an estimate read off the current in-game sight markings. Fire a spotting round before sustained fire. Ballistics and weapon limits change as the game is developed.

This is an unofficial, fan-made utility. It is not affiliated with, endorsed by or connected to the developers of WARDOGS. The formulas and the sight-marking table are derived from the community IDF calculator at schaulers.com.
```

The screenshots are real captures of the release build on a Galaxy S25 Ultra,

## 4. App content declarations

**Data safety** — answer *No* to data collection and *No* to data sharing.
The app collects and transmits nothing, so every follow-up question about
encryption in transit, deletion requests and data types is skipped. Justify it
with the manifest: there is no `INTERNET` permission.

**Content rating questionnaire** — category *Utility, Productivity,
Communication or Other*. Answer honestly:

| Question | Answer |
|---|---|
| Violence | References weapons and indirect fire for a video game. No depictions, no imagery, no gameplay. |
| Sexuality, language, controlled substances, gambling | None |
| User-generated content, sharing, messaging | None |
| Location sharing, personal information | None |

Expected outcome is a low rating — PEGI 7 or ESRB Everyone 10+ territory.
Whatever IARC returns is what applies; do not argue it down.

**Target audience** — 13 and over. Do not opt into the Designed for Families
programme; it adds policy obligations this app gains nothing from.

**Ads** — no. **In-app purchases** — no. **Government app** — no.
**Financial features** — none.

**App access** — all functionality is available with no login, no region lock
and no special setup. Say so; otherwise Play asks for test credentials.

## 5. Naming risk, stated once

The listing carries the game's name. Play's impersonation policy is aimed at
apps that appear official, which is what the disclaimer paragraph in the full
description above is there to prevent. It is not a guarantee. This is recorded
because it was a deliberate decision, not an oversight.

## 6. Signing key

Play needs a release build signed with an upload key. The repository holds no
key and no password; CI reads them from GitHub secrets.

**Generate the key (you).** Android Studio does it without a terminal:
*Build → Generate Signed App Bundle → Create new…*. With a JDK installed it is
also one command:

```bash
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
```

No JDK on this machine yet; `winget install Microsoft.OpenJDK.17` provides
`keytool`.

**Back the file up somewhere you will still have in five years.** With Play App
Signing enrolled — the default for new apps — Google holds the actual app
signing key and yours is only the upload key, so a lost upload key can be
reset by support. Without it, a lost key ends the app.

**Store it for CI (you).** Four secrets, set from a shell where the keystore is:

```bash
base64 -w0 upload.jks | gh secret set KEYSTORE_BASE64 --repo Hapnes-dev/wardogs-idf
```

```bash
gh secret set KEYSTORE_PASSWORD --repo Hapnes-dev/wardogs-idf
```

```bash
gh secret set KEY_ALIAS --repo Hapnes-dev/wardogs-idf
```

```bash
gh secret set KEY_PASSWORD --repo Hapnes-dev/wardogs-idf
```

The last three prompt for the value and do not echo it. Type the passwords
yourself; nobody else needs to see them.

Until `KEYSTORE_BASE64` exists, the release job still runs and signs with the
debug key, so the R8 output stays testable. Play rejects debug-signed uploads,
so that fallback cannot reach the store by accident.

## 7. Building the upload

Push to `main`, or run the workflow manually. The `release` job produces:

| Artifact | Use |
|---|---|
| `app-release.aab` | the file Play accepts |
| `app-release.apk` | sideload testing of the same minified build |
| `mapping.txt` | upload alongside the bundle so crash reports deobfuscate |

`versionCode` comes from the workflow run number, so it increases on every
build and Play never sees a repeat. `versionName` lives in `gradle.properties`
and is the string users see; bump it by hand for a release worth naming.

## 8. Order of operations

1. **you** — create the account, pay, accept the agreement
2. **you** — create the upload keystore, back it up, set the four secrets
3. Push; download `app-release.aab` from the run artifacts
4. **you** — create the app in Play Console, paste the text from section 2,
   upload the graphics from section 3
5. **you** — complete the declarations in section 4
6. **you** — upload the bundle and the mapping file to a closed testing track
7. **you** — recruit 12 testers, run 14 consecutive days
8. **you** — promote to production

Steps 3 is the only one that is not yours, and it is already automated.
